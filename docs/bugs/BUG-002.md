# BUG-002: Issues: an issue can be marked a duplicate of itself

- **Component:** Issues > Duplicates
- **Priority:** P3
- **Found by:** `tests/test_planted_defects.py::test_bug002_...`, SQL check `02_self_duplicate.sql`

## Summary
`POST /api/issues/{id}/duplicate` validates that the original exists but not that it is a
different issue.

## Steps to reproduce
1. Create issue 1.
2. `POST /api/issues/1/duplicate` with `{"duplicate_of": 1}`.

## Expected result
HTTP 422 with a clear message.

## Actual result
HTTP 200, issue 1 now shows "Duplicate of #1".

## Impact
Bad data. The duplicate-finder and reports that follow `duplicate_of` links can loop or hide a real
issue. Workaround: clear the field by hand in the database.

## Suspected cause
Missing `issue_id == duplicate_of` guard in `IssueService.mark_duplicate`. A fuller fix should also
reject chains that form a cycle (A dupe of B, B dupe of A).

## Suggested regression test
Strict xfail test exists; add a cycle test (A -> B -> A) when fixing.
