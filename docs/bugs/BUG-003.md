# BUG-003: Search: text search is case-sensitive and the priority filter returns higher priorities

- **Component:** Search
- **Priority:** P2
- **Found by:** `tests/test_planted_defects.py::test_bug003_*`, exploratory session 2

## Summary
Two defects in `GET /api/issues`:
- **(a)** `q=crash` does not find "App will Crash on launch" (case-sensitive match).
- **(b)** `priority=P2` returns P1 and P2 issues. The filter uses `<=` on the string.

## Steps to reproduce
(a) Create an issue titled "App will Crash on launch", then search `q=crash`.
(b) Create one P1 and one P2 issue, then filter `priority=P2`.

## Expected result
(a) The issue is found. (b) Only the P2 issue is returned.

## Actual result
(a) Empty list. (b) Both issues.

## Impact
Users miss existing issues (which leads to duplicates being filed) and triage views are polluted
with higher-priority items. Workaround: search in the exact casing; filter client-side.

## Suggested regression tests
Strict xfail tests exist for both parts. Also add boundary cases: `P4` (lowest), unknown
priority value `P9` (should be 422, currently returns everything).
