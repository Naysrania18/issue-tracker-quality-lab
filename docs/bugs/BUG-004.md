# BUG-004: Events: a re-delivered event creates a second notification

- **Component:** Notifications
- **Priority:** P3
- **Found by:** `tests/test_planted_defects.py::test_bug004_...` (event tests)

## Summary
`NotificationConsumer.handle` never remembers `event_id`. Queues normally deliver "at least once",
so a retry or a duplicate publish sends the same notification twice.

## Steps to reproduce
1. Build an `IssueCreated` event.
2. Pass the same event object to `NotificationConsumer.handle` twice.
3. Count rows in `notifications`.

## Expected result
One row.

## Actual result
Two rows with the same `event_id`.

## Impact
Users receive repeated notifications whenever delivery is retried.

## Suggested fix
Add a `UNIQUE` constraint on `notifications.event_id` and ignore the conflict, or keep a set of
processed ids. The constraint is better because it also survives a restart.

## Related
Out-of-order delivery *is* handled (per-issue sequence number), see `test_events.py`.
