# BUG-005: Web UI: HTML in an issue description is rendered unescaped (stored XSS)

- **Component:** Web UI > Issue detail
- **Priority:** P1
- **Found by:** exploratory session 2, `tests/test_planted_defects.py::test_bug005_...`

## Summary
The issue detail template renders the description with Jinja's `|safe` filter. Any HTML or script
a user types is written to the page for every viewer.

## Steps to reproduce
1. Log in as any user and create an issue with description `<script>alert(1)</script>`.
2. Open the issue detail page.

## Expected result
The text `<script>alert(1)</script>` is shown literally.

## Actual result
The markup is inserted into the page and the script runs.

## Impact
An attacker with a reporter account can run script in the session of an engineer or QA user who
opens the issue (session cookie theft, actions on their behalf). The cookie is `HttpOnly`, which
limits theft but not forged actions.

## Suspected cause
`{{ issue.description|safe }}` in `issue_detail.html`. All other fields use auto-escaping.

## Suggested fix and regression test
Remove `|safe`. Keep the strict xfail test, plus a UI test in `ui_tests/` that creates an issue
containing markup and asserts the rendered text equals the typed text.
